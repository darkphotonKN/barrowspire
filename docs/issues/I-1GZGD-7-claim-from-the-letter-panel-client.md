## What to Build

The one "Take" button on a letter with unclaimed enclosures (`claimState` `unclaimed` or
`claiming`), calling `POST /api/mail/letters/{id}/claim` through the generated client:

- "Take" → "Taking…", disabled → on success ("Taken"): the Enclosed slots dim, a "Taken" wax
  stamp, the button gone, the list row's enclosure glyph dims, the envelope's seal count drops,
  and any gold balance the client shows is refetched.
- `STASH_FULL` → warning line "Your stash needs N free slots" (N = the letter's slot count, the
  sum of its item quantities), button stays.
- `LETTER_EXPIRED` → "This letter has crumbled to dust." and the letter leaves the list.
- `LETTER_ALREADY_CLAIMED` → the letter shown taken.
- `LETTER_CLAIM_IN_PROGRESS` and any other failure → "The seal would not break. Try again.",
  button stays.

No take-all (D9). The button never sends twice from one panel (disabled while in flight); the
server guards the rest. The screen never says "Claim".

**Files it expects to touch:** the panel and presenter modules created by I-1GZGD-6
(`game-client/src/ui/mailbox/*` or equivalent) and their tests. **Does not** touch
`HubScene.ts`, `BarrowspireScene.ts`, `SocketManager.ts` or `src/api/generated/` (regenerated by
I-1GZGD-4).
