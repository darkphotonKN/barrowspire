**Lane: client (agent lane).**

## What to Build

The one "Claim" button on a letter with unclaimed enclosures (`claimState` `unclaimed` or
`claiming`), calling `POST /api/mail/letters/{id}/claim` through the generated client:

- Claim → "Claiming…", disabled → on success: the Enclosed slots dim, a "Claimed" wax stamp, the
  button gone, the list row's enclosure glyph dims, the envelope's seal count drops, and any gold
  balance the client shows is refetched.
- `STASH_FULL` → warning line "Your stash needs N free slots" (N = the letter's slot count, the
  sum of its item quantities), button stays.
- `LETTER_EXPIRED` → "This letter has crumbled to dust." and the letter leaves the list.
- `LETTER_ALREADY_CLAIMED` → the letter shown claimed.
- `LETTER_CLAIM_IN_PROGRESS` and any other failure → "The seal would not break. Try again.",
  button stays.

No claim-all (D9). The button never sends twice from one panel (disabled while in flight); the
server guards the rest.

**Files it expects to touch:** the panel and presenter modules created by I-1GZGD-6
(`game-client/src/ui/mailbox/*` or equivalent) and their tests. **Does not** touch
`HubScene.ts`, `BarrowspireScene.ts` or `src/api/generated/` (regenerated by I-1GZGD-4).

## Acceptance Criteria

- [ ] Claim walks Claim → "Claiming…" (disabled) → claimed: dim slots, "Claimed" stamp, no button,
      dim list glyph, lower seal count, gold refetched.
- [ ] `STASH_FULL` shows "Your stash needs N free slots" with the letter's slot count; the button
      stays.
- [ ] `LETTER_ALREADY_CLAIMED` shows the letter claimed; `LETTER_EXPIRED` shows the crumbled line
      and drops it; any other failure shows "The seal would not break. Try again." with the button
      kept.
- [ ] The button is absent on a letter with no enclosures or already claimed.
- [ ] Presenter unit tests cover every state above; typecheck, lint and the token fence pass.
- [ ] Manual check in the browser: claim a letter with items and gold; a second tab's claim is
      refused and shows claimed after reload.
