> **Amended 2026-11-04** (FS-1GZGD amendment A2, A4): no polling timer — the summary is fetched on
> the `mail_arrived` WebSocket action, on town entry and on opening the panel; the Enclosed row
> draws from each enclosure's stored item snapshot (`item`), not a read-time preview. The
> client's `mail_arrived` handling is built and unit-tested here against a faked message; the
> live push check is I-1GZGD-7's, once I-1GZGD-8 and -9 are in.

## What to Build

Everything a player sees of the mailbox except claiming (I-1GZGD-7), wired into the town once.

- **Envelope** (R33): a line envelope with a small wax seal, drawn with Phaser graphics (no
  emoji, no Heroicons, no baked art), at the bottom-right of the town HUD only; never mounted in
  a delve or field world.
- **Fetching the summary** (R34, A4): `GET /api/mail/summary` through the generated client on
  town entry (including coming back from a delve or a field), on each `mail_arrived` action
  (`{"action": "mail_arrived", "payload": {}}`) received while in the town, and on opening the
  panel. **No timer.** `SocketManager` routes `mail_arrived` to the mailbox (a store or a
  listener, as `chat` / `party_update` are routed); outside the town it is ignored.
- **Seal and pulse** (R35): lit with `waitingCount` when > 0, dark at 0; when `newestLetterAt`
  (from any of the three fetches) is newer than the last value seen, the envelope pulses a few times then stays lit. The
  last-seen value is kept per player in browser storage, every access in try/catch; without it,
  the first summary records without pulsing.
- **Letter panel** (R36–R38, R40): a centered carved panel (`carvedPanel.ts`, `menuChrome.ts`,
  `game-client/docs/design-guideline.md`): list left (title, relative time, enclosure glyph;
  unread bright + lit seal dot, read dim), letter right (title, sender "The Barrowspire Wardens" /
  "The Spire", sent date, days left in the warning tone at ≤ 3, scrollable plain-text body).
  Opening selects the first unread, else the newest; selecting marks read via
  `POST /api/mail/letters/{id}/read` and updates the seal at once. Empty: "No letters wait for
  you." × and Esc close; while open WASD does not move the character (the same gate chat input
  uses). `LETTER_EXPIRED` on read → "This letter has crumbled to dust." and the letter leaves the
  list.
- **Enclosed row** (R37), read-only here: bag-sized slots with the existing item icon
  (`itemIcon` on the enclosure's stored snapshot, `item`) and the existing item tip built from
  that snapshot on hover, "x3" for quantity > 1, gold as a `coins` slot with its amount under it (S8). Absent on a
  letter without enclosures. The Take button is I-1GZGD-7.

Keep the panel's logic Phaser-free where the repo does (presenter + view, as `ChatWindow` /
`party` do) so copy and state are unit-tested without a canvas.

**Files it expects to touch:** `game-client/src/scenes/HubScene.ts` (mount the envelope and panel
next to `mountChatWindow` / `mountPartyPanel`, fetch on town entry, add the panel to the input
gates — the **only** issue that touches a scene file; `BarrowspireScene.ts` and `FieldScene.ts` are not touched);
new `game-client/src/ui/mailbox/*` (or `src/ui/MailboxEnvelope.ts`, `src/ui/LetterPanel.ts`,
`src/mailbox/*` presenter + api calls) with tests; possibly
`game-client/src/ui/carvedPanel.ts` / `menuChrome.ts` only to reuse, not change;
`game-client/src/utils/class/SocketManager.ts` (route `mail_arrived`, the **only** issue that
touches it) and a mailbox store or listener module under `src/stores/` or `src/mailbox/`. Uses the
generated client regenerated by I-1GZGD-3; never edits `src/api/generated/`.

## Acceptance Criteria

- [ ] The envelope is shown in the town bottom-right and never in a delve or field world.
- [ ] The summary is fetched on town entry, on each `mail_arrived` in the town and on opening the
      panel; no timer fetches it; a `mail_arrived` outside the town fetches nothing.
- [ ] The seal is lit with `waitingCount` when > 0 and dark at 0; a newer `newestLetterAt`
      pulses the envelope a few times, then it stays lit; storage failures do not break it.
- [ ] The panel lists letters as D14 describes, selects the first unread (else the newest) on
      open, and marking read dims the row and lowers the seal at once, without another fetch.
- [ ] The Enclosed row shows item icons with the item tip drawn from each stored snapshot (a
      copied unique shows its affixes), "x3", and a `coins` slot with the amount; it is absent on
      a letter without enclosures.
- [ ] Empty mailbox: "No letters wait for you."; × and Esc close; WASD does not move the character
      while open.
- [ ] `LETTER_EXPIRED` shows "This letter has crumbled to dust." and drops the letter.
- [ ] Unit tests for the presenter (selection, seal state, pulse rule, copy) and for the fetch
      triggers (a faked `mail_arrived` fetches once; none in a delve; none on a timer); typecheck,
      lint and the token fence pass.
- [ ] Manual check in the browser: envelope, pulse on a letter sent while away (seen at town
      entry), reading.
